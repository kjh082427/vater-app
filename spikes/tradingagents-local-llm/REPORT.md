**품질 관찰 (보고서 원문을 읽고 확인)**
- 4b × AAPL: 차트 보고서가 비었고, 옵션 내재변동성·풋콜 비율 같은 **받지 않은 수치를 지어냈다.** Research Manager와 Trader는 구조화 출력(JSON)에 실패해 자유 텍스트로 다시 시도했다.
- 4b × 005930.KS: 재무 보고서가 "데이터를 확인할 수 없다"고 쓰면서도 일반론으로 채웠고, **회사 이름을 "삼성전기"로 틀렸다.** 본문에 중국어·일본어 한자(`负债`, `長期負債`)가 섞였다.
- 9b × AAPL: 보고서는 모두 채워졌고 한국어 비율도 가장 높았다(감성·재무까지 57~80%). 하지만 8GB에서는 1.1GB가 CPU로 넘어가 시간이 클라우드의 6배다.
- 같은 종목·같은 날짜인데 결정이 Hold / Sell / Buy / Underweight / Hold(S5)로 갈렸다 → 리포트 화면에 "모델과 실행에 따라 결론이 달라질 수 있음"을 표시한다.
- 9b × 005930.KS는 **실행하지 않았다.** 9b가 8GB에 다 올라가지 않는다는 결론은 AAPL로 이미 나왔고(국내 종목이어도 모델 크기는 같다), 1시간짜리 실행보다 S5·S8 측정에 GPU 시간을 쓰는 편이 판단에 더 도움이 됐다.

**결론**
- 8GB 등급: 추천 로컬 모델은 `qwen3.5:4b`를 유지하되(다 올라가고 완주함) **기본 프리셋은 클라우드로 바꾼다.** 4b의 보고서 품질이 투자 판단 보조로 쓰기에는 부족하다(스펙 13장 S1의 "실패하면" 대안).
- `qwen3.5:9b`는 8GB 등급의 대안에서 "비추천"으로 내린다. 12GB 이상 등급에서는 다 올라갈 것으로 보이지만 이 PC로는 측정하지 못했다.
- 카탈로그의 "예상 시간"은 8GB × 4b = 22분(미국 종목 기준)으로 둔다.

## S2. 국내 종목 데이터 품질
- **측정:** `inspect_data.py`, 기준일 2026-10-30(과거)과 2026-11-02(최근 거래일), 2026-11-03 01:40 KST 실행
- **종목:** `AAPL`, `005930.KS`(삼성전자), `247540.KQ`(에코프로비엠)

| 데이터 종류 | AAPL | 005930.KS | 247540.KQ |
|---|---|---|---|
| 가격 1년 (`get_stock_data`) | ✅ | ✅ (하루 지연) | ✅ (하루 지연) |
| 기술 지표 RSI·MACD (`get_indicators`) | ✅ | ✅ | ✅ |
| 기업 개요 (`get_fundamentals`) | ❌ 공개 시점 규칙으로 제외 | ❌ 같은 이유 | ❌ 같은 이유 |
| 재무제표 (`get_balance_sheet`, `get_income_statement`) | ✅ SEC EDGAR | ❌ SEC 없음 + yfinance 제외 | ❌ 같은 이유 |
| 종목 뉴스 7일 (`get_news`) | ✅ (최근 거래일 기준만, 과거 날짜는 ❌) | ❌ Yahoo에 국내 종목 뉴스 없음 | ❌ 같은 이유 |
| 내부자 거래 (`get_insider_transactions`) | ❌ 공개 시점 규칙으로 제외 | ❌ | ❌ |

**발견**
1. TradingAgents v0.7.1은 **point-in-time 원칙**(분석 기준일에 실제로 공개돼 있던 데이터만 씀)을 엄격히 지킵니다. 공개일이 없는 yfinance 재무·개요·내부자 데이터는 오늘 날짜라도 항상 제외합니다. 미국 재무제표는 공개일이 있는 SEC EDGAR가 대신합니다.
2. 국내 종목은 **가격과 기술 지표만** 쓸 수 있습니다. 재무와 종목 뉴스가 없으므로 기본 설정의 펀더멘털·뉴스 애널리스트는 "데이터 없음" 보고서만 냅니다.
3. Yahoo의 국내 일봉은 하루 늦게 들어옵니다(11/2 종가가 비어 있어 10/30을 최신으로 씀).

**결론 (스펙 13장 S2의 "실패하면" 대안 적용)**
- 국내 종목은 **소셜 애널리스트를 끕니다**(스펙 5장 원안 그대로).
- 국내 종목용 데이터 공급자 **`kis`를 1차 버전 `core/analysis`에 추가**합니다. TradingAgents의 `VENDOR_METHODS`에 등록하고, `.KS`/`.KQ` 종목에만 `tool_vendors`로 지정합니다.
  - 가격: 한투 일봉(지연 없음)
  - 재무: 한투 국내주식 재무비율·손익계산서·대차대조표 API
  - 뉴스: 한투 종합 시황·공시 제목 API
  - 앱은 "최근 거래일" 분석이므로 현재값을 그대로 제공합니다. point-in-time 제약은 백테스트용이라 1차 버전 범위가 아닙니다.
- DART 키가 없어서 DART 어댑터는 2차 버전에 그대로 둡니다.
- 한투의 재무·뉴스 API를 실제로 쓸 수 있는지는 `core/kis` 첫 작업에서 확인합니다. 안 되면 국내 종목은 펀더멘털·뉴스 애널리스트를 끄고 차트·거시 분석만 합니다.

## S3·S4·S6. 출력 언어, 결정값, 진행 스트리밍
- **측정:** `run_spike.py --ticker AAPL --preset local-4b --lang Korean` (실행 `run-20261103-020336-AAPL-local-4b`)

### S3. 한국어 출력
- `DEFAULT_CONFIG["output_language"]`로 설정합니다(기본값 `"English"`). 설정하면 **뒤쪽 단계는 한국어로** 나옵니다.

| 보고서 | 한글 비율 |
|---|---|
| 뉴스 | 63% |
| 리서치 매니저 투자 계획 | 53% |
| 트레이더 | 73% |
| 최종 결정 | 61% |
| **감성·재무 애널리스트** | **0% (영어)** |

- 나머지 비율은 "Gross Profit Margin" 같은 영어 용어라 정상 범위입니다.
- **결론:** 한국어 요약 단계를 따로 만들지 않고 `output_language="Korean"`을 씁니다. 다만 일부 애널리스트 보고서는 영어로 나오므로, UI에서는 **최종 결정과 3줄 요약을 한국어로 우선 보여주고**, 애널리스트 원문 탭에는 "원문(영어일 수 있음)"이라고 표시합니다.

### S4. 결정값 체계
- 5단계 등급 **Buy / Overweight / Hold / Underweight / Sell**입니다. 읽어낼 수 없으면 `REVIEW`가 됩니다(`tradingagents.agents.rating.run_rating`).
- 한국어 출력에서도 결정문 첫 줄이 `**Rating**: Sell`처럼 영어로 유지돼서 **추출이 정상**입니다.
- **결론:** UI 결정 배지는 5단계와 "검토 필요(REVIEW)"를 합쳐 6개 상태입니다. 한국어 표기는 매수 / 비중확대 / 보유 / 비중축소 / 매도 / 검토 필요입니다.

### S6. 진행 스트리밍
- `TradingAgentsGraph.graph.stream(입력, subgraphs=True, stream_mode=["updates", "values"])`를 `run_config_context(config)` 안에서 돌리면 노드 단위 이벤트를 받을 수 있습니다.
- 애널리스트는 각자 서브그래프에서 돌기 때문에 namespace(`"Market Analyst:<uuid>"`)로 누구의 단계인지 구분됩니다. `agent`와 `tools` 노드가 번갈아 나오므로 도구 호출 라운드도 셀 수 있습니다.
- 최상위 노드는 `Bull Researcher`, `Bear Researcher`, `Research Manager`, `Trader`, `Aggressive Analyst`, `Conservative Analyst`, `Neutral Analyst`, `Portfolio Manager` 순서로 나옵니다.
- 애널리스트 4명은 **병렬로** 실행됩니다.
- **결론:** 스펙 5장의 노드 단위 타임라인을 그대로 구현할 수 있습니다. `analysis/engine.py`는 위 방식으로 진행 이벤트를 `EventBus`에 발행합니다.
- 참고: 토큰 수는 LLM 클라이언트 콜백(`usage_metadata`)으로 집계됩니다. 도구 호출은 콜백으로 잡히지 않아서 노드 이벤트로 셉니다.

## S5. 체크포인트로 이어서 실행
- **측정:** `run_spike.py --ticker AAPL --preset local-4b --checkpoint`를 12분 시간 제한으로 돌려 중간에 끊고(앱이 비정상 종료된 상황), 같은 명령을 다시 실행했다. 계획은 "두 번째 노드 이벤트에서 종료"였지만, 토론 단계까지 진행된 뒤 끊어야 "건너뛰었는지"가 분명히 보여서 12분으로 정했다.

| 실행 | 결과 | 소요 시간 | LLM 호출 | 처음 나온 노드 | 애널리스트 도구 호출 |
|---|---|---|---|---|---|
| 1차 (12분에 중단) | 시간 초과 | 12.4분 | 14 | Memory Log → 애널리스트 4명 → Bull → Bear | 6회 |
| 2차 (다시 실행) | ✅ 완주, Hold | 13.9분 | 7 | **Research Manager**부터 | **0회** |

- 2차 실행은 애널리스트 4명과 강세·약세 토론을 다시 돌리지 않았다. 처음부터 다시 돌렸다면 약 22분이 걸렸을 것이다.
- 체크포인트 파일: `<data_cache_dir>/checkpoints/<종목>.db` (LangGraph SqliteSaver). 스레드 ID는 종목·기준일과 그래프 구성(애널리스트 조합, 설정)으로 정해진다. **설정이 바뀌면 이어지지 않고 새로 시작한다.**
- 완주하면 `clear_checkpoint_on_success`로 지운다.

**결론**
- 스펙 5장대로 `checkpoint_enabled=True`를 켠다. 앱은 실패하거나 강제 종료된 분석을 [다시 시도]할 때 **같은 종목·기준일·프리셋**으로 실행하면 이어진다.
- `data_cache_dir`는 앱 데이터 폴더 아래(`%APPDATA%\Vater\cache\tradingagents`)로 둔다.
- 1차와 2차를 합친 시간(26.3분)은 한 번에 끝낸 실행(21.6분)보다 길다. 끊긴 단계의 LLM 호출은 버려지기 때문이다.

## S8. 혼합 프리셋 (로컬 quick + 클라우드 deep)
- **측정:** `run_spike.py --ticker AAPL --preset mixed` = quick `ollama/qwen3.5:4b-16k`, deep `google/gemini-3.8-flash`. 계획은 005930.KS였지만, 같은 조건의 클라우드·4b 실행과 바로 비교하려고 AAPL로 했다(국내 종목은 어차피 `kis` 공급자로 바뀐다).
- 설정: `llm_provider="ollama"`, `quick_think_provider="ollama"`, `quick_think_backend_url=http://localhost:11434/v1`, `deep_think_provider="google"`. TradingAgents v0.7.1의 `tier_provider`/`create_tier_client`가 단계별로 다른 제공자를 만든다.

| 프리셋 | 완주 | 소요 시간 | LLM 호출 | 토큰 (입력/출력) | 빈 보고서 | 결정 |
|---|---|---|---|---|---|---|
| 클라우드 | ✅ | 9.5분 | 17 | 71.6K / 12.9K | 없음 | Hold |
| 로컬 4b | ✅ | 21.6분 | 19 | 94.0K / 55.6K | 차트 | Sell |
| **혼합** | ✅ | **38.6분** | 17 | 92.4K / 53.0K | 없음 | Underweight |

- 두 제공자가 모두 기록됐고(`models.deep = google`, `models.quick = ollama`) 예외는 없었다.
- **가장 느렸다.** deep 단계 2개가 오래 걸렸다: Research Manager 약 5분, Portfolio Manager 약 13.7분. 클라우드 전용 실행에서도 Portfolio Manager가 6분 걸렸으므로, Gemini 무료 등급 deep 모델의 응답 지연(또는 호출 제한 대기)으로 보인다. 4b가 만든 긴 보고서(재무 8.7K자)를 입력으로 받은 것도 한 원인이다.
- 애널리스트 보고서는 여전히 4b가 쓰므로 품질 문제(S1)가 그대로 남는다.

**결론**
- 혼합 프리셋은 **동작하므로 프리셋에서 빼지 않는다**(스펙 13장 S8의 "실패하면" 조건에 해당하지 않음).
- 8GB 등급의 기본값으로는 쓰지 않는다(S1). 12GB 이상 등급(9b 이상이 다 올라감)의 기본값으로 남긴다. 단, 이 등급은 측정하지 못했다.
- 혼합 프리셋을 고르면 "로컬 모델이 애널리스트 보고서를 씁니다. 클라우드보다 느리고 품질이 낮을 수 있습니다"를 설정 화면에 표시한다.
