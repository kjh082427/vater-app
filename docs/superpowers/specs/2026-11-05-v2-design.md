# Vater v2 설계

> **살아 있는 문서다.** 구현 중 결정이 바뀌면 이 문서를 고친다.

- 상위 설계: `2026-11-02-vater-mvp-design.md`, `2026-11-03-dashboard-design.md`
- 앱 버전: v1 = `0.1.0`, v2 = **`0.2.0`**. 공개 릴리스 저장소 `vater-releases`와 업데이트 주소는 그대로 쓰고 `v0.2.0` 릴리스를 더한다(`v0.1.0`은 남겨 둔다).

## 0. 목표와 조건

**목표:** 사용자가 증권사를 연결하면, 계좌별 보유 종목·수량·평단가를 **불러올 수 있게** 한다. 불러온 종목 중 고른 것을 감시 종목에 올리고, 여러 증권사에 나뉜 보유 현황을 한눈에 본다.

**조건**
- **주문·정정·취소 기능은 넣지 않는다.** 이 키들은 주문까지 가능한 키이고 조회 전용 키는 확인되지 않았으므로, 막는 책임은 앱에 있다(8장).
- 시세와 알림은 계속 한투로 한다. **한투 키는 필수다.** 다른 증권사는 보유 조회만 한다.

**지원 범위**

| 증권사 | 방식 | 근거 |
|---|---|---|
| 한국투자, 키움, 메리츠 | API 연결 | `docs/brokers/*.md` (`core/broker-*` 브랜치) |
| 삼성, 미래에셋 | 수동 입력 | 개인용 REST API 근거를 찾지 못함 |
| 그 밖 | 수동 입력, 증권사 직접 추가 | |

## 1. 증권사 연결
- 위치: 설정 > 증권사 연결. 첫 실행 마법사는 지금처럼 한투만 필수이고 나머지는 "나중에"가 가능하다.
- 입력: 앱키, 시크릿, 계좌번호(증권사별 필요 여부는 노트 참고). 연결 테스트를 통과해야 저장한다.
- **저장 단위는 "연결 = 증권사 + 계좌"다.** 메리츠는 키를 계좌별로 발급하므로 계좌가 둘이면 연결도 둘이다.
- 키는 Windows 자격 증명 관리자에 쓰기 전용으로 둔다. 계좌번호는 가려서 표시한다(`****1234`). 계좌번호를 받지 않는 키움과 메리츠는 앱키 해시 앞 4자리로 구분한다(`키 ab12`). 계좌 구분은 이 연결 목록에서만 보인다.
- 한투는 종합계좌(뒤 2자리 `01`)만 연결한다. 연금 등은 조회 TR이 달라 v2에서 받지 않는다. 연결은 만들 때의 서버(실전·모의)를 기억한다. 서버를 바꾸면 그 연결은 갱신하지 않고 옛 수량을 유지하며, 실전과 모의 연결을 함께 둘 수 없다.
- 메리츠는 모든 요청에 MAC 주소가 필수다. 앱이 PC에서 읽어 보내고, 무엇을 왜 보내는지 연결 화면에 안내한다.

### 1-1. 연결 해제
- **사용자가 해제할 때:** "미래에셋 연결을 해제했습니다"를 알리고, 그 증권사의 기존 데이터를 삭제할지 묻는다. 키는 어느 쪽이든 지운다.
- **연결이 끊겼을 때**(키 만료, 키움 3개월 미접속 자동 해지 등): 증권사별로 "연결이 끊겼습니다"를 알리고 [다시 연결] / [데이터 삭제]를 보인다. 저장된 수량은 마지막 갱신 시각과 함께 유지한다.
- **삭제하면:** 그 증권사 계좌의 보유 내역(수량, 평단가)을 앱에서 모두 지운다. 수동 입력 증권사도 같다. 종목 합계와 칩은 바로 다시 계산한다.
- **삭제해도 남는 것:** 자산 추이의 지난 기록, 감시 종목과 규칙(사용자가 따로 고른 것). 확인 창에 이를 적어 둔다.
- 삭제하지 않으면 보유 내역은 "연결 해제됨" 표시와 함께 합계에 계속 들어간다.
- **[다시 연결]은 고른 옛 연결을 대신한다.** 새 연결의 테스트와 첫 조회가 모두 성공해야 옛 연결과 내역을 지운다. 실패하면 옛 내역이 그대로 남는다. 해제하면 계좌번호도 지우므로 앱이 같은 계좌인지 추정하지 않는다. 같은 증권사에 끝 4자리가 같은 해제 연결이 있으면 화면에서 "이전 내역을 이 연결로 바꿀까요?"를 묻는다.
- 연결 중인 증권사의 데이터만 지울 수는 없다(다음 갱신 때 다시 채워진다). 먼저 해제한다.

## 2. 업로드 (감시·알림 화면, 검색창 위)
- 버튼은 연결한 증권사만 보인다. 예: `[메리츠] [한투] [연결한 증권사 모두]`
- 어느 버튼을 눌러도 같은 확인 창을 거친다. 바로 올라가지 않는다.
  - 기본은 전부 체크. 전체 선택·해제가 있다.
  - "이미 감시 중"은 체크할 수 없게 표시한다.
  - "지원하지 않는 종목"(ETN, 국내·미국 외 시장 등)은 이유와 함께 표시한다.
  - 증권사 하나가 실패해도 나머지는 보여 주고, 실패한 곳만 오류를 표시한다.
- **보유 내역은 항상 전부 저장한다. 체크는 감시 종목에 넣을지만 정한다.** 그래야 일부를 해제해도 총 수량과 평단가가 맞다.
- 같은 종목이 여러 증권사에 있으면 감시 종목은 하나로 합친다.
- 판 종목은 수량만 0이 되고 감시 종목에서 빼지 않는다. 새로 산 종목은 자동으로 넣지 않고 버튼에 "새 종목 N개"로 알린다. 확인 창에서 한 번 본 종목은 체크를 해제했어도 새 종목으로 세지 않는다.

## 3. 갱신

**보유 수량**
- 앱 시작 때 한 번, [새로 고침] 버튼.
- 주기 조회는 설정에서 고른다: **끔(기본) / 10분 / 30분 / 1시간.** 장이 열린 시간에만 돈다.

**주가** (실시간 규칙이나 폴링 규칙이 없는 종목)
- 설정에서 고른다: **30초 / 1분 / 5분 / 10분(기본) / 30분 / 1시간.** 장이 열린 시간에만 돈다.
- 최소 30초인 이유: 사이드카가 종목당 30초 동안 시세를 재사용한다(`QUOTE_FRESH`). 한투 호출 한도는 실전 초당 15회가 기본이라 100종목도 약 7초에 끝나지만, 모의 서버는 초당 2회라 약 50초가 걸린다.
- 규칙이 있는 종목은 이 설정과 상관없이 지금처럼 실시간 또는 폴링으로 받는다. **알림 시간은 바뀌지 않는다**(실시간 5초, 폴링 60초 기준).
- 평가금액 옆에 시세 시각을 표시한다. 10분 주기면 최대 10분 전 가격일 수 있기 때문이다.

## 4. 보유 현황

### 4-1. 계산
- 합산 평단가 = Σ(계좌 수량 × 계좌 평단가) ÷ 총 수량. 증권사가 준 평단가를 쓴다.
- 평가금액 = 총 수량 × 현재가. 평가손익 = 평가금액 − Σ(수량 × 평단가). 수익률 = 평가손익 ÷ 매입금액.
- 현재가는 앱의 한투 시세를 쓴다. 증권사 앱과 시점과 평단가 계산 방식이 달라 값이 조금 다를 수 있음을 안내한다.
- 수동 항목은 평균 매수가가 필수다(5장). API 응답에 평단가가 없는 경우에만 그 수량을 손익 계산에서 빼고 표시한다.
- 시세가 없으면 평가금액과 손익은 "—"로 표시한다. 값을 지어내지 않는다.
- 종목별 값은 그 종목의 통화로 보인다. 전체 합계는 통화별로 보이고, 원화 환산은 자산 추이(12장)와 같은 환율을 쓴다.

### 4-2. 표시 위치
- **종목 화면의 주가 그래프 바로 아래 "내 보유" 카드.** 그래프는 v1에 없어 새로 만든다(4-4).
  ```
  [주가 그래프]
  내 보유                                            [새로 고침]
  평가금액 1,071,000원        평가손익 +111,000원 (+11.6%)
  총 15주 · 평단가 64,000원                       시세 14:05
  [■■■■■■■■■■■ 한투 ■■■■■ 메리츠]
  ● 한투 10주   ● 메리츠 5주
  ```
- **감시 종목 표:** 보유, 평단가, 평가손익 열을 더한다. 칸이 좁으면 평단가부터 숨긴다.
- **대시보드:** 칸 내용 "내 보유 종목"과 숫자 카드 "총 평가금액", "총 평가손익"(통화별)을 더한다.

### 4-3. 표기
- 칩을 누르면 `메리츠 5주` ↔ `메리츠 33.3%`로 바뀐다. 칩 전체가 함께 바뀌고 마지막 선택을 기억한다. 비율은 총 수량 중 그 증권사의 몫이다.
- 한 증권사의 여러 계좌는 칩 하나로 합친다.
- 수량은 미국 주식만 소수점을 표시한다(`0.5주`). 저장은 정밀한 소수로 한다.
- 평가손익은 방향 색을 쓴다(이익 빨강, 손실 파랑).

### 4-4. 주가 그래프
- 일봉 선 그래프. 기간은 **1개월 / 3개월 / 1년**이다. 디자인 시스템의 `LineChart`를 쓴다. 선 색은 방향 색이다(그날의 등락).
- 보유 중이면 내 평단가를 점선으로 긋는다(`LineChart`의 `baseline`). 보유하지 않으면 전일 종가 없이 선만 그린다.
- v1의 종목 화면에는 그래프가 없으므로 종목별 일봉 조회 API를 새로 만든다. 캔들 차트는 v2에 넣지 않는다.

## 5. 수동 입력
- [보유 종목 직접 추가]: 종목 검색 → 증권사 클릭 → 수량 → 평균 매수가(1주당). **네 항목 모두 필수다.** 수정·삭제가 된다.
- 증권사는 타이핑하지 않고 클릭으로 고른다. 삼성과 미래에셋을 기본 제공하고, [증권사 추가]로 이름을 한 번 등록한다.
- "직접 입력" 표시와 입력 날짜를 보여 준다. API 갱신이 수동 항목을 덮어쓰지 않는다.

## 6. 알림 규칙
- 업로드 기본값은 "규칙 없음"이다. 확인 창에서 규칙을 하나 골라 체크한 종목에 한꺼번에 적용할 수 있다.
- 목표가 규칙(`price_above`, `price_below`)은 종목마다 값이 달라 일괄 적용에서 뺀다.
- **실시간 감시 안내(금지하지 않음):** "실시간 감시는 최대 41종목입니다. 넘는 종목은 약 30초마다 가격을 확인해 알림을 보냅니다." 실시간 규칙을 적용하거나 규칙 편집기에서 만들 때, 현재 사용량(예: 38/41)과 함께 보인다. 41은 한투 구독 한도(`kis.ws_max_subscriptions`), 30초는 `alerts.poll_interval_sec`의 기본값이며, 설정값에 맞춰 표시한다. 규칙이 없는 종목은 이 한도를 쓰지 않는다.

## 7. 색

| 용도 | 색 |
|---|---|
| 상승 | `#E60000` (원색 `#FF0000`은 대비 4.00으로 기준 미달) |
| 하락 | `#0000FF` |
| 한국투자 | `#7B634F` 갈색 |
| 메리츠 | `#D14C34` 빨강 |
| 키움 | `#D4467D` 핑크 |
| 삼성 | `#1C2FA7` 파랑 |
| 미래에셋 | `#D97A00` 주황 (이미지의 `#EC662A`는 메리츠와 색상 차이가 9°뿐이라 25°로 벌림, 대비 3.12) |
| 직접 추가한 증권사 | 초록, 청록, 보라 계열에서 자동 배정 |

- 규칙 변경: **숫자 글자의 빨강·파랑은 방향 전용, 증권사 색은 막대와 칩의 점에만.** 증권사 이름은 검정 글자로 항상 함께 쓴다. `DESIGN.md`와 토큰 테스트를 함께 고친다.
- 막대의 칸 사이에는 흰 틈을 둔다.

## 8. 주문 금지
- 지금의 `test_readonly_guarantee.py`는 한투 패턴만 막는다. 키움과 메리츠의 주문 경로·TR을 더한다.
- 증권사마다 쓸 수 있는 API를 허용 목록으로 고정한다.
- 어댑터는 보유 조회 함수만 가진다.

## 8-1. 개인정보는 AI에 보내지 않는다 (최우선, 2026-11-05 확정)
- 계좌번호, 보유 내역(수량, 평단가, 금액, 비중, 보유 종목 목록), 이용 증권사, 수동·CSV 입력값은 **어떤 AI에도 보내지 않는다.** 클라우드와 로컬 모두 해당한다.
- AI가 받는 것은 공개 시장 자료와 감시 종목(코드, 이름, 시세)이다. 종목 분석에는 사용자가 그 분석에서 고른 종목과 공개 자료만 들어간다.
- **감시 종목은 보내도 된다(사용자 결정, 2026-11-05). 보유 종목은 안 된다.** 감시 종목에는 보유 내역에서 올린 종목도 있으므로, AI 입력에 그 종목의 보유 여부나 출처를 표시하지 않는다.
- AI에 닿는 코드(`analysis/`, `briefing/interpret.py`, `llm/`)는 보유 내역 모듈을 불러오지 않는다. 테스트로 막는다.

## 9. 구현 전 확인할 것
- 평단가 응답 필드: 한투 `pchs_avg_pric`(2차 자료), 키움과 메리츠 미확인
- 나머지는 `docs/brokers/*.md`의 "확인할 것"

## 10. 브랜치와 순서
1. `core/holdings`: 공통 틀(연결, 보유 내역, 수동 입력, CSV의 DB와 API, 주문 금지 가드)
2. `core/broker-kis` → `core/broker-kiwoom` → `core/broker-meritz`: 코드는 main의 `sidecar/src/vater_core/brokers/`에 합친다
3. `core/portfolio`: 주가 조회 주기, 일봉 API, 자산 추이와 환율, 평단가 알림, 브리핑 개인화
4. `core/categories`: 업종 분류표 만들기와 검색 API
5. `ui/holdings`: 색, 연결 화면, 업로드 창, 내 보유 카드와 그래프, 수동 입력과 CSV, 대시보드 칸, 분류 탐색
6. 확인 테스트 → `v0.2.0` 릴리스(`infra/*`는 고칠 일이 있을 때만)

## 11. 분류로 종목 찾기
- 종목 검색 화면에서 **시장 선택 [한국 | 미국 | 통합]** 뒤에 대 → 중 → 소로 들어간다. 어느 단계에서 멈춰도 그 아래 종목을 모두 보여 준다. 시장은 층이 아니라 선택 칸이고 기본값은 **통합**이다. 고른 분류는 유지한 채 시장만 바꿀 수 있다.
- 키워드 검색 대상: 종목 이름 + 분류 이름 + 테마별 키워드(직접 작성).
- **분류표는 앱에 파일로 넣고 앱 업데이트로 갱신한다.** 사용자에게 키를 받지 않는다. 한 종목이 여러 분류에 들어갈 수 있다. 분류에 없는 종목은 "미분류"이고 이름 검색으로는 찾을 수 있다.

| 단계 | 내용 | 자료 |
|---|---|---|
| 대분류 | 직접 정한 묶음 10~15개 | 직접 작성 |
| 중분류 | 테마 26개를 대분류 아래 둔다. 미국은 SEC의 SIC 코드를 테마에 잇고, 맞는 테마가 없으면 한글 이름의 중분류를 새로 둔다 | 직접 작성 + 공개 자료를 개발 때 가공 |
| 소분류 | v2에는 두지 않는다. 더 넓히는 것은 v3 | |

- 테마 26개: 반도체, 2차전지, AI·소프트웨어, 인터넷·플랫폼, 로봇, 통신, 제약, 바이오, 의료기기, 자동차, 자동차 부품, 조선, 방산, 항공우주, 원자력·전력기기, 건설, 철강, 화학·정유, 해운·물류, 식품, 화장품, 게임, 엔터·미디어, 은행, 증권, 보험
- 테마별 종목은 공개된 사실을 바탕으로 AI가 초안을 만들고 사용자가 표로 검수한다. 투자 권유로 읽히지 않게 쓴다.
- **거래소(KRX) 자료는 쓰지 않는다.** 법적고지가 사전 동의 없는 복제와 배포를 막는다(2026-11-06 확인). 그래서 국내 세부 업종 탐색과 주요제품 검색은 v2에 없다. v3에서 이용 조건이 분명한 공공 자료를 확인한 뒤 다시 본다. WICS와 GICS도 쓰지 않는다.
- SEC 자료는 요청자를 밝히는 User-Agent가 필요하다. 개발 때만 받고, 값은 git에서 제외된 루트 `.env`의 `SEC_USER_AGENT`에서 읽는다. 앱은 SEC를 부르지 않는다. 구현 전에 SEC 자료의 이용 조건을 확인한다.

## 12. 자산 추이
- 총 보유 주식의 평가금액을 매일 기록해 그래프로 본다. 대시보드 칸 "자산 추이"로 제공하고, 기간은 1개월 / 3개월 / 1년 / 전체다.
- 기록은 장 마감 뒤 종가로 하루 한 번 한다. 보유 수량 주기 조회가 꺼져 있어도 이 기록을 위해 하루 한 번은 조회한다. 그날 앱이 꺼져 있었으면 다음 실행 때 마지막 보유 수량과 그날 종가로 채우고, 채운 날임을 저장한다.
- 그래프에 평가금액과 매입금액 두 선을 긋는다. 주식을 더 사도 평가금액이 오르므로, 이것이 수익인지 입금인지 구별하기 위해서다.
- **보기 전환: 전체(원화 환산) / 원화 / 달러.** 기본은 전체다. 전체는 그날 환율로 달러 자산을 원화로 바꿔 더한다. 환율 때문에 선이 움직일 수 있으므로 화면에 적용 환율과 미국 비중을 표시한다.
- 환율은 한투 API로 받는다(`FHKST03030100`, 시장 `X`, 종목 `FX@KRW`, 2026-11-05 실제 호출로 확인: 당일과 과거 일별 값이 온다). **하루 한 시점의 값만 쓴다.** 그날 처음 필요할 때 받아 저장하고, [새로 고침]을 누르면 다시 받는다. 날마다 기록할 때 그날 환율도 함께 저장한다. 조회에 실패하면 전체 보기에 "환율 없음"으로 표시하고 원화·달러 보기는 그대로 둔다.
- 첫 연결 이후부터 기록한다. 과거 추이는 복원하지 않는다. 주식만 포함하고 예수금(현금)은 넣지 않으므로 화면에 "주식 평가금액"으로 표기한다.

## 13. 평단가 기준 알림
- 새 규칙 종류: 평단가 대비 ±N%. 예: 평단가 대비 −10%.
- **기본은 끔이다.** 내 보유 카드에서 종목별로 켜거나, 업로드 창의 일괄 적용에서 고른다(퍼센트라 일괄 적용 가능). 실시간 규칙이므로 41종목 한도를 쓴다.
- 평단가는 합산 평단가(4-1)를 쓴다. 전량 매도하면 평가하지 않는다.

## 14. CSV 가져오기
- 수동 입력 화면의 [파일로 가져오기]: 파일 선택 → 증권사 클릭 → 미리보기 → 올리기. 올리기는 2장의 확인 창과 같다(보유 내역은 저장, 체크는 감시 종목 여부).
- 열은 이름으로 자동 추정하고(종목명·종목코드, 수량, 평균 매수가), 틀리면 사용자가 고른다. 증권사마다 형식이 달라도 동작하게 하기 위해서다. 한글 CSV는 CP949와 UTF-8을 모두 읽는다.
- 필수 값이 빠진 행과 찾지 못한 종목은 이유와 함께 보여 주고 올리지 않는다. 같은 이름의 종목이 여럿이거나 이름이 정확히 맞지 않으면 후보에서 사용자가 고른다. 파일 하나는 1,000행까지다.
- 같은 증권사로 다시 가져오면 그 증권사의 수동 항목을 파일 내용으로 바꾼다. 바꾸기 전에 달라지는 내용을 보여 준다.
- v2는 CSV만 지원한다. 삼성·미래에셋이 내려받는 파일 형식은 샘플로 확인한다. 엑셀(xlsx)이 필요하면 샘플을 본 뒤 정한다.

## 20. AI 분석 재시도와 대체 모델 (2026-11-06 확정)
- 배경: Gemini 무료 등급에서 실제 분석 3건이 모두 실패했다. 원인은 서버 혼잡(503)과 모델별 분당 한도(429, 분당 15회)였고, 앱은 2번만 재시도했다. 유료 API는 쓰지 않는다(무료로만 운영).
- **기다렸다가 다시 시도한다.** 503과 429는 구글이 알려 준 대기 시간만큼 기다리고, 알려 주지 않으면 점점 길게 기다린다. 한 모델에서 약 3분까지 버틴다.
- **그래도 안 되면 다음 무료 모델로 넘어간다.** 빠른 작업은 `gemini-3.5-flash-lite` → `gemini-3.1-flash-lite` → `gemini-2.5-flash-lite`, 깊은 판단은 `gemini-3.8-flash` → `gemini-3.5-flash` → `gemini-2.5-flash`. 바꾼 모델은 결과 화면에 표시한다. 사용자가 설정에서 모델을 직접 정했으면 그 모델을 먼저 쓴다.
- 다 실패하면 분석은 실패로 끝나고, 마친 단계는 저장되어 [다시 시도]가 이어서 한다.
- 키가 틀렸거나 권한이 없는 오류는 재시도하지 않는다.
- 오류 문구:

| 상황 | 문구 |
|---|---|
| 혼잡해서 기다리는 중 | 구글 AI 서버가 혼잡합니다. 잠시 후 자동으로 다시 시도합니다. |
| 분당 한도 초과 | 무료 사용량의 분당 한도에 걸려 잠시 기다립니다. |
| 하루 한도 초과 | 오늘 무료 사용량을 다 썼습니다. 내일 다시 시도하거나 로컬 AI로 바꿔 주세요. |
| 끝내 실패 | 분석을 끝내지 못했습니다. 마친 단계는 저장됐으니 잠시 뒤 [다시 시도]를 눌러 주세요. |

- **분석 메모리를 끈다.** TradingAgents의 메모리 로그는 다른 종목의 분석 기록을 AI 입력에 넣어 8-1장에 어긋난다. 사용자가 답하지 않아 추천안대로 정했다(2026-11-06). 다시 켜려면 사용자 결정이 필요하다.

## 21. v0.2.1 (2026-11-06 확정, 사용자가 써 보며 고른 것)
1. **분석 이력 삭제:** 실패했거나 원하지 않는 분석을 지운다. 그 분석의 보고서와 중간 저장분(체크포인트)도 함께 지운다. 진행 중인 분석은 지울 수 없다.
2. **감시 종목과 보유 종목 정리**
   - 감시 종목 목록에서 보유한 종목과 보유하지 않은 종목을 나눠 보인다. 이 표시는 화면에만 쓰고 AI에 보내지 않는다(8-1).
   - 왼쪽 메뉴에 **"보유 종목" 탭**을 새로 둔다. 보유 종목의 가격, 등락, 평가금액, 손익, 증권사별 수량을 본다. 보유 종목 올리기, 직접 입력, CSV 가져오기는 이 탭으로 옮긴다.
   - 감시·알림 화면에서 [보유 종목 직접 추가]를 뺀다. 감시 종목을 추가하는 버튼으로 오해되어 실제로 보유 내역에 잘못 들어간 사례가 있었다. 감시 종목 카드의 첫 동작은 종목 검색으로 추가하기다.
3. **분석 창에서 보유 종목 고르기:** "감시 종목에서 고르기" 옆에 둔다. 분석 요청에는 고른 종목 하나만 들어가고 보유 여부는 들어가지 않는다.
4. **직접 입력 뒤 감시 종목 제안:** 보유 내역을 직접 넣으면 "감시 종목에도 추가할까요?"를 묻는다. 입력 창에는 보유 내역을 넣는 곳이라고 분명히 적는다.
5. **브리핑 AI 해석:** 분석과 같은 재시도와 대체 모델(20장)을 쓴다. 해석 없이 저장된 브리핑은 나중에 자동으로 다시 시도하고, 화면에 [AI 해석 다시 만들기]를 둔다. 해석이 없을 때는 이유를 보인다. 브리핑 AI 입력의 범위(8-1)는 바꾸지 않는다.
