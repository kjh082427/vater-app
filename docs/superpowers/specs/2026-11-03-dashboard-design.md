# Vater 대시보드 개편 설계 (홈 = 사용자가 짜는 대시보드, 새 시각 디자인)

- 날짜: 2026-11-03
- 상위 설계: `docs/superpowers/specs/2026-11-02-vater-mvp-design.md`. 이 문서는 그 9장(화면 구성)의 홈과 시각 디자인을 바꾼다. 나머지 장은 그대로다.
- 시안: `design-preview/대시보드-시안/`(로컬 전용). 채택한 것은 **1 · 대시보드 라이트**이고, 편집 화면의 단계 안내(①②③)는 3번 안에서 가져온다.

## 0. 왜, 무엇을

**사용자가 한 말(2026-11-03)**
- 1차 화면 초안을 본 뒤 "UI 디자인을 싹 갈아엎고 싶다"고 했다. 참고로 보여 준 것은 Power BI 대시보드다.
- 원하는 것: "사용자가 원하는 방식으로 화면을 구성"한다. "최대한 자유도를 주되, 오류가 없는 선에서"다. 한 화면에 필요한 칸의 개수를 정하고, 그 칸들을 어떻게 배치할지, 칸마다 무엇을 띄울지를 **쉽게** 정한다.
- 결정: "내 화면 여러 장"으로 한다. **왼쪽의 고정 메뉴(홈·분석·감시·알림·브리핑·설정)는 유지한다.**
- 시각 디자인도 개편한다. 시안 선택은 사용자가 리드에게 맡겼다("알아서 마무리까지").

**성공 기준**
1. 처음 쓰는 사람이 [배치 편집] → 칸 수 → 배치 틀 → 칸 내용 → [저장]으로 새 화면 하나를 **1분 안에** 만든다.
2. 어떤 조작을 해도 칸이 겹치거나, 가려지거나, 내용의 최소 크기보다 작아지지 않는다. 저장된 배치가 깨져 있어도 앱은 기본 배치로 열린다.
3. 칸 하나의 내용이 실패해도(오류, 자료 없음) 다른 칸과 앱은 그대로다.
4. 배치는 앱 업데이트·재설치 뒤에도 남는다.
5. 새 디자인은 스펙 9-1의 관례(상승 빨강·하락 파랑, 원·달러 표기, 면책)를 지키고, 글자 대비는 WCAG AA다.

**하지 않음(YAGNI)**
- 칸을 자유롭게 띄우는 창(겹치는 창)은 만들지 않는다.
- 칸 사이 연동 그룹(여러 종목 묶음 연동)은 만들지 않는다.
- 어두운 테마는 이번에 만들지 않는다(시안 2는 기록만).
- 화면 배치 내보내기·가져오기도 만들지 않는다.
- 시뮬레이션 칸은 v1.1에서 만든다. 목록에 "곧 추가"로만 보인다.

## 1. 구조

- **왼쪽 메뉴**는 유지한다: 홈 · 분석 · 감시·알림 · 브리핑 · 설정. 분석·감시·알림·브리핑·설정 페이지는 내용과 흐름이 그대로이고 새 디자인으로 다시 입힌다.
- **홈**은 대시보드 탭 여러 장이다(최대 8장).
  - 탭: 이름 바꾸기, 추가(+), 삭제(확인 대화상자, 마지막 1장은 삭제 불가), 왼쪽·오른쪽으로 옮기기.
  - 처음 설치하면 기본 탭 1장 "기본"이 있다. 칸은 4개로 지수 차트 · 브리핑 요약 · 감시 종목 · 최근 알림이고, 맨 위 숫자 줄이 켜져 있다.
- **대시보드 1장** = 맨 위 숫자 줄(켜기·끄기, 숫자 카드 최대 5개) + 칸 1~6개 배치.
- **칸 1개** = 내용 1가지 + 그 내용의 옵션(예: 시장, 종목) + 칸 머리(제목, 설명 한 줄, `⋯` 메뉴: 내용 바꾸기·새로 고침).
- 칸 안의 행이나 링크를 누르면 해당 페이지로 간다(9-3과 같다). 감시 종목 행 → `#/symbols/:market/:code`, 알림 → 알림 대상, 브리핑 → `#/briefings/:id`, 분석 → `#/analyses/:id`.

## 2. 배치: 틀 + 경계선

배치는 **분할 나무**로 나타낸다. 칸들이 대시보드 영역을 빈틈없이 나눠 쓰므로 겹침이 원리상 생기지 않는다.

```ts
type Split = { dir: 'row' | 'col'; sizes: number[]; children: Node[] }; // sizes 합 = 1
type Node = Split | { panel: number };                                    // panel = 칸 번호(0부터)
```

**배치 틀**(칸 수별, 코드에 고정된 목록, id로 저장)

| 칸 수 | 틀 |
|---|---|
| 1 | 한 칸 |
| 2 | 좌우 반반, 위아래 반반 |
| 3 | 왼쪽 크게 + 오른쪽 2, 위 크게 + 아래 2, 가로 3열 |
| 4 | 2×2, 왼쪽 크게 + 오른쪽 3, 위 크게 + 아래 3, 가로 4열 |
| 5 | 위 2 + 아래 3, 왼쪽 크게 + 오른쪽 2×2 |
| 6 | 2×3, 3×2 |

**경계선 끌기**
- 같은 분할의 인접 두 칸 비율을 바꾼다. 키보드로도 된다(경계선에 초점을 둔 뒤 ←/→ 또는 ↑/↓로 5%씩).
- 끄는 동안 비율 표시(예: 58 : 42)가 보인다.

**최소 크기**
- 내용마다 최소 크기(px)가 있다(3장).
- 경계선은 양쪽 칸이 최소 크기 아래로 내려가지 않는 지점에서 멈춘다.

**맞지 않는 틀**
- 편집 화면에서 지금 창 크기의 대시보드 영역에 넣었을 때 어느 칸이든 최소 크기보다 작아지는 틀은 고를 수 없다. 이유를 함께 보인다(예: "창이 작아 들어가지 않음: 칸 너비 약 250px < 감시 종목 최소 360px").
- 내용 고르기 목록에서도 그 칸 크기에 맞지 않는 내용은 이유와 함께 막는다.

**창이 저장한 때보다 작아지면**
- 배치를 바꾸지 않는다. 대시보드 영역은 최소 크기를 지키고 세로·가로로 스크롤된다. 망가지지 않고 스크롤만 생긴다.

**검증**
- 불러온 배치는 다음 순서로 확인한다.
  1. 틀 id가 있고, 칸 수가 맞는가
  2. sizes가 양수이고 합이 1(오차 0.001)인가
  3. 비율이 최소 크기를 어기면 틀의 기본 비율로 되돌린다
- 내용 종류를 모르면(새 버전에서 생긴 것) 그 칸에 "이 버전에서 지원하지 않는 내용입니다 [내용 바꾸기]"를 보인다.
- 문서 전체가 깨졌으면 기본 배치로 열고 정보 배너를 보인다: "저장된 화면 배치를 읽지 못해 기본 배치로 열었습니다."

## 3. 칸 내용 목록

| id | 이름 | 자료 | 옵션 | 최소 크기 |
|---|---|---|---|---|
| `watchlist` | 감시 종목 | `/watchlist/quotes` + SSE `quote`, 상태 `feeds` | 시장(전체/국내/미국) | 360×180 |
| `index-chart` | 지수 차트 | `/market/indices`(새 API, 4장) | 지수(코스피/코스닥/S&P 500/나스닥) | 300×180 |
| `briefing` | 브리핑 요약 | `/briefings`(최신 1건) | 시장(국내/미국) | 300×180 |
| `recent-alerts` | 최근 알림 | `/alerts/events?limit=` + SSE `alert.fired` | 없음(칸 높이에 맞춰 5~10건) | 280×160 |
| `running-analyses` | 진행 중인 분석 | `/analyses` + SSE `analysis.*` | 없음 | 280×140 |
| `analysis-result` | 분석 결과 | `/analyses/:id` | 종목(최근 완료 분석 중 선택) 또는 "가장 최근" | 360×240 |
| `alert-history` | 알림 이력 | `/alerts/events` | 종목·종류(화면에서 거름) | 360×220 |
| `kpi` | 숫자 카드 | 아래 숫자 목록 | 숫자 1~4개 선택 | 260×96 |
| `simulation` | 시뮬레이션 | (v1.1) | | 목록에 "곧 추가"로만 |

- 같은 내용을 두 칸에 둘 수 있다(옵션이 다를 수 있으므로).
- **숫자 목록**(맨 위 숫자 줄과 `kpi` 칸이 같이 쓴다): 코스피, 코스닥, S&P 500, 나스닥(현재값·전일 대비·등락률), 감시 종목 수(상승·하락), 오늘 알림 수, 진행 중인 분석 수, 외국인 순매수(최근 국내 브리핑, 억).
- **각 칸은 자기 오류 경계를 가진다.** 실패하면 그 칸에만 `{message, hint}`와 [다시 시도]를 보인다. 빈 상태는 무엇을 하면 되는지 알려 준다(예: "감시 종목이 없습니다 · 종목 추가").

## 4. 사이드카 추가 (읽기 전용, 주문 없음)

**`GET /ui/dashboards`, `PUT /ui/dashboards`**: 대시보드 문서 저장(성공 기준 4)
- 문서: `{version: 1, dashboards: [{id, name, kpi: {enabled, items[]}, layout: {template, root: Node}, panels: [{type, options}]}]}`
- 사이드카가 확인하는 것: 크기 64KB 이하, `version`, 대시보드 1~8장, 이름 1~20자, 칸 1~6개, JSON 형태. 내용 종류·옵션의 뜻은 화면이 확인한다(새 내용 종류를 추가할 때 사이드카를 바꾸지 않기 위해).
- 틀리면 422 `DASHBOARD_INVALID` + hint.
- 저장 위치는 settings DB의 별도 키(`ui.dashboards`, 일반 설정 목록과 검증 경로는 따로)다. 없으면 `GET`은 `{version: 1, dashboards: []}`를 주고, 화면은 이때 기본 배치를 쓴다.

**`GET /market/indices`**: 지수 칸과 숫자 카드용
- 응답: `[{code, name, market, value, change, change_pct, at, closes: number[30]}]`(코스피·코스닥·S&P 500·나스닥).
- 이미 있는 `index_quote`·`index_daily`·`overseas_index`를 `Priority.ALERTS`보다 낮게 부르고, 30초 캐시와 동시 요청 합치기를 한다.
- 지수 하나가 실패하면 그 지수만 `value: null`로 준다. 한투 키가 없으면 전부 `null`이고 오류 응답은 아니다.
- 이번 개편의 지수 차트는 **최근 30거래일 종가 + 오늘 현재값**이다. 장중 분봉 흐름은 하지 않는다(남은 일).

## 5. 시각 디자인 (1 · 대시보드 라이트)

- **바탕과 카드**
  - 바탕: 밝은 회색 캔버스
  - 칸: 흰 카드(모서리 8px, 아주 옅은 그림자, 안쪽 여백 16px), 카드 머리는 제목(16px 굵게) + 설명 한 줄(13px)
- **강조색은 보라(인디고-바이올렛) 하나다.** 선택, 주 버튼, 활성 탭, 링크에 쓴다. 빨강·파랑은 **값의 방향에만** 쓴다. 지수 표지 같은 분류 표시에도 빨강·파랑을 쓰지 않는다(시안의 코스피 빨강·코스닥 파랑 네모는 중립색으로 바꾼다).
- **표:** 머리줄은 어둡고(짙은 남색 바탕, 흰 글자) 줄마다 옅은 교차 바탕이다. 숫자 열은 오른쪽 정렬, 고정폭 숫자.
- **숫자 카드:** 큰 숫자(28px), 작은 이름표, 아래에 전일 대비·등락률, 오른쪽에 미니 차트.
- **글꼴:** Pretendard 하나(이미 번들된 서브셋). 이전 디자인의 Hahmlet(명조) 제목은 쓰지 않는다.
- **차트:** 직접 그린 SVG다(차트 라이브러리를 들이지 않는다).
  - 선·영역 차트: 방향 색, 전일 종가 점선
  - 가로 막대(수급): 순매수 빨강·순매도 파랑, 0 기준선
  - 축 눈금 12px
- **상태 표시줄·사이드바 아래 감시 상태:** 지금 정보 구성 그대로, 새 색으로.
- **편집 화면**
  - 위 줄: [배치 편집 · 탭 이름] [취소] [저장]
  - 오른쪽 설정 창: ① 몇 칸으로 나눌까요 ② 어떤 모양으로 놓을까요(틀 그림, 막힌 틀은 자물쇠와 이유) ③ 맨 위 숫자 줄
  - 캔버스: 칸마다 번호, 내용 이름, [내용 바꾸기 ▾] 목록(2열, 막힌 내용은 이유), 경계선 손잡이와 비율 표시
  - 아래: "기본 배치로 되돌리기"
  - 칸 수를 줄이면 앞 번호 칸의 내용을 유지하고, 늘리면 새 칸은 "내용 고르기" 빈칸이다. 저장 전에 빈칸이 있으면 [저장]이 비활성이고 이유를 보인다.
  - [취소]나 Esc는 바꾸기 전으로 돌아간다. 바꾼 것이 있으면 확인한다.
- **디자인 시스템:** `DESIGN.md`와 토큰을 새 방향으로 다시 쓴다. 이전 디자인 시스템 부품은 겉모습만 바꾸고 API(이름·속성)는 되도록 유지한다. 그래야 기존 화면 테스트가 대부분 그대로 산다.
- **새 부품(이전 리뷰의 빈틈 포함):** Card(칸), KpiTile, Select, Popover/Menu, Toggle, SegmentedControl, Dialog, TextField, LineChart, DivergingBar, 진행 막대. FeedStatus에는 `idle`을 넣고, DataTable이 비어 있을 때의 머리줄도 고친다.

## 6. 오류 처리

| 상황 | 동작 |
|---|---|
| 대시보드 문서 저장 실패(422·연결 끊김) | 편집 화면을 유지하고 오류 `{message, hint}`를 보인다. 바꾼 내용은 잃지 않는다 |
| 문서를 읽지 못함(깨짐) | 기본 배치 + 정보 배너. 다음 저장 때 덮어쓴다 |
| 모르는 내용 종류 | 그 칸만 안내 + [내용 바꾸기] |
| 칸 내용 실패 | 그 칸만 오류와 [다시 시도]. 다른 칸은 그대로 |
| 창이 작아짐 | 배치는 그대로, 대시보드 영역 스크롤 |
| 사이드카 재시작·SSE 끊김 | 기존 연결 층 그대로(오프라인 배너, 다시 연결되면 칸마다 다시 불러오기) |

## 7. 테스트

- **배치 엔진(순수 함수, Vitest):**
  - 틀마다 칸 수와 영역 합
  - 경계선 끌기가 최소 크기에서 멈춤
  - 틀이 맞는지 판정(1024×600, 1280×800)
  - 검증과 기본값으로 되돌리기
  - 칸 수를 바꿀 때 내용 유지
- **편집 화면(RTL + MSW):**
  - 성공 기준 1의 흐름
  - 막힌 틀과 막힌 내용의 이유
  - 빈칸이 있으면 저장 비활성
  - 취소·Esc
  - 저장 실패 시 편집 유지
  - 키보드로 경계선 조절
- **칸 내용:** 내용마다 정상·빈 상태·오류. 한 칸이 실패해도 다른 칸이 그려짐. 숫자 표기와 색(방향만 빨강·파랑).
- **사이드카(pytest):**
  - `/ui/dashboards` 저장·읽기·422(크기, 장 수, 칸 수, 형태)·재시작 뒤 유지
  - `/market/indices` 캐시·부분 실패·키 없음
  - OpenAPI 스냅샷
- **흐름 테스트(Playwright, 실제 개발 모드 사이드카):** 탭 추가 → 3칸 틀 → 내용 고르기 → 저장 → 새로 고침 뒤 그대로. 경계선 끌기. 1024×600에서 막힌 틀.
- **디자인 확인:** 토큰 대비 테스트(AA), impeccable 검출기 0건, 캡처 1280×800·1024×600·배율 1.5.
