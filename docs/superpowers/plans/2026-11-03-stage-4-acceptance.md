# 4단계(셸·화면) 확인 테스트 계획

> 사용자 요청(2026-11-03): "각 단계 완료할 때마다 꼼꼼한 테스트 케이스 만들어서 테스트 진행까지 완료해줘."
> 2026-11-03 사용자 결정으로 홈이 대시보드로 바뀌므로, U(화면)는 `ui/dashboard`가 합쳐진 뒤 그 화면으로 한다. U1의 "홈"은 기본 대시보드, U14 등은 대시보드 칸을 포함한다.
> 작업별 단위 테스트와 별도로, 4단계 전체를 **사람이 앱을 쓰는 흐름대로** 묶어 확인한다. 둘 다 통과하면 main에 `stage-4-shell-ui` 태그.

**Goal:** 화면과 셸이 스펙 0장 성공 기준 중 4단계 몫을 지키는지 확인한다.
- 1번: 관리자 권한 없이 설치, 첫 실행 마법사 완료
- 2번: 창을 닫아도 트레이에서 감시가 계속되고, 알림이 5초 안에 화면에 뜸
- 6번: 화면 코드에도 주문 경로가 없음

또 8장 오류 처리 표 중 화면과 셸이 맡는 줄, 그리고 9-3 화면 이동을 확인한다.

**Spec:** `docs/superpowers/specs/2026-11-02-vater-mvp-design.md` 0장, 2-1, 2-2, 8장, 9장, 10장

**방식:** 이미 있는 코드를 확인하는 테스트다. 실패하면 그것이 찾은 버그이고, 해당 영역 브랜치(`ui/*`, `shell/*`, `core/*`)에서 실패하는 테스트로 재현해 고친다. 영역이 둘이라 브랜치도 둘이다.

## U. 화면 ↔ 실제 사이드카 프로세스 (Playwright)

**판(stack):** 화면은 Vite 개발 서버의 실제 화면이다. 사이드카는 **실제 FastAPI 앱 + 실제 감시 루프·분석 큐·브리핑 서비스**이고, 바깥 서비스만 가짜로 둔다.
- 가짜로 두는 것: 한투 REST·WebSocket, TradingAgents 엔진, LLM
- 실행: `e2e/acceptance/stack.py`를 `uv run --project sidecar`로 띄운다. `create_app(AppDeps)`에 가짜를 주입하고 uvicorn으로 띄운 뒤 `ready{port}`를 출력한다(3단계 확인 C와 같은 조립).
- 시계: 국내 장중에서 시작한다.
- 셸 흉내: Playwright `addInitScript`로 가짜 Tauri 다리(`__TAURI_INTERNALS__`)를 넣는다. 이 다리는 `get_sidecar_info`에 **지금 살아 있는 실제 사이드카**의 포트와 토큰을 돌려주고, 테스트가 `sidecar-state`와 `navigate`를 보낼 수 있게 한다. 그래서 화면은 Tauri 경로(`createTauriPlatform`)로 돈다.

**실행:** `cd apps/desktop && npm run e2e:acceptance` (19개, 약 5분). 판은 `e2e/acceptance/stack.py`(실제 사이드카 + 가짜 한투·엔진·LLM)와 `harness.ts`(가짜 Tauri 셸, 화면 출처 `http://tauri.localhost` → Vite 5183)다. 파일은 흐름 테스트와 섞이지 않게 `*.accept.ts`로 둔다. 창 크기는 1920×1080(대시보드 칸이 좁으면 수신 열을 뺀다).
- 감시 시계는 화 10:00 KST(장중), 브리핑 시계는 화 16:00 KST(장 마감 뒤)로 따로 둔다.
- 알려진 차이(스펙 위반 아님): 실패한 분석은 단계별 시간이 저장되지 않아 실패 화면 타임라인이 모두 "진행 안 됨"이다.
