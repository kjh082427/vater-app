# core/llm 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** LLM 엔진 관리 계층을 만든다. 하드웨어 감지, 모델 카탈로그, Ollama 관리(상태·시작·설치·모델 받기·삭제·16K 변형), 클라우드 키 연결 테스트, 그리고 **프리셋을 TradingAgents 설정과 환경변수로 바꾸는 함수**까지다.

**Architecture:**
- `sidecar/src/vater_core/llm/` 아래 작은 모듈로 나눈다. TradingAgents는 import하지 않는다(의존성은 `core/analysis`가 추가). 이 계층은 TradingAgents `DEFAULT_CONFIG` 위에 덮어쓸 **덮어쓰기 dict**와 **환경변수 dict**만 만든다.
- Ollama는 httpx로 `http://localhost:11434`를 부른다. 모델 받기·설치는 백그라운드 작업으로 돌리고 진행률을 `EventBus`(`llm.pull`, `llm.install`)로 보낸다.
- 라우트는 `api/routes/llm.py` 하나. 상태(진행 중인 작업, 하드웨어 감지 캐시)는 `AppDeps.llm`의 `LlmState`가 갖는다.

**Tech Stack:** httpx(스트리밍), 기존 foundation(SettingsRepo, SecretStore, EventBus, VaterError), respx(테스트)

**Spec:** `docs/superpowers/specs/2026-11-02-vater-mvp-design.md` 3장(프리셋, 설치 흐름, 카탈로그), 2-3(API), 8장(오류). 근거 자료: `spikes/tradingagents-local-llm/REPORT.md`(S1, S3, S8).

## Global Constraints
- 브랜치 `core/llm`, 폴더 `sidecar/src/vater_core/llm/`, `sidecar/src/vater_core/api/routes/llm.py`. PR 라벨 `area:core`.
- **API 키는 환경변수로만 넘긴다.** 덮어쓰기 dict에는 절대 키 값을 넣지 않는다. 환경변수 이름은 TradingAgents v0.7.1 `api_key_env.py` 기준: `google→GOOGLE_API_KEY`, `anthropic→ANTHROPIC_API_KEY`, `openai→OPENAI_API_KEY`, `openai_compatible→OPENAI_COMPATIBLE_API_KEY`.
- 기타 서버(compat)의 주소는 비밀키 `LLM_COMPAT_BASE_URL`(자격 증명이 섞일 수 있음)이고, TradingAgents 제공자 이름은 `openai_compatible`이다.
- 클라우드 키 연결 테스트에서 **키를 URL 쿼리에 넣지 않는다**(헤더만). 로그에 남지 않게 하기 위해서다.
- Ollama 주소 `http://localhost:11434`, OpenAI 호환 주소 `http://localhost:11434/v1`.
- 로컬 모델은 `num_ctx`를 고정한 변형 `<tag>-<num_ctx/1024>k`(예: `qwen3.5:4b-16k`)를 만들어 쓴다. TradingAgents에 `num_ctx` 설정이 없기 때문이다(S1에서 확인).
- 프리셋 정의(스펙 3-1): `cloud` = quick·deep 모두 클라우드 / `local` = 모두 로컬 / `mixed` = quick 로컬, deep 클라우드.
- 하드웨어 감지: `nvidia-smi --query-gpu=name,memory.total --format=csv,noheader,nounits`, **시간 제한 5초**. 실패하면 내장 GPU로 본다.
- Ollama 설치 파일은 `https://ollama.com/download/OllamaSetup.exe`. 실행 전에 **Authenticode 서명 검사**(PowerShell `Get-AuthenticodeSignature`, Status `Valid`, 서명자에 `Ollama` 포함)를 통과해야 한다. 설치 창은 사용자가 진행한다(스펙 3-2-4).
- 오류는 모두 `VaterError(code, message, hint, status)`. 이 브랜치에서 새로 쓰는 코드:
  - `LLM_KEY_MISSING` 409, `LLM_KEY_INVALID` 400, `LLM_UNREACHABLE` 503, `LLM_LOCAL_MODEL_MISSING` 409, `LLM_MODEL_UNKNOWN` 404, `LLM_PULL_IN_PROGRESS` 409
  - `OLLAMA_NOT_RUNNING` 503, `OLLAMA_ERROR` 502, `OLLAMA_INSTALL_UNSUPPORTED` 409, `OLLAMA_INSTALL_IN_PROGRESS` 409, `OLLAMA_INSTALLER_UNTRUSTED` 502
- 테스트에서 실제 네트워크·GPU·Ollama를 쓰는 것은 `@pytest.mark.llm`(기본 제외)뿐이다.

## Review Focus
1. **Ollama가 설치되지 않았거나 꺼져 있음** → `status()`는 예외 없이 `installed=False`/`running=False`를 돌려준다. 분석 직전 확인(`GET /llm/check`)은 `OLLAMA_NOT_RUNNING`으로 알린다. (Task 3, 7)
2. **모델 받기 도중 연결이 끊기거나 Ollama가 오류 줄을 보냄** → 진행 이벤트가 `status:"error"`로 끝나고 작업 목록에서 빠져서, 같은 모델을 다시 받을 수 있다(Ollama가 이어 받는다). (Task 3, 7)
3. **VRAM보다 큰 모델** → `/api/ps`의 `size_vram < size`면 `offloaded=True`. (Task 3)
4. **클라우드·혼합 프리셋인데 키가 없음** → `LLM_KEY_MISSING`(409). 로컬·혼합인데 로컬 모델이 없음 → `LLM_LOCAL_MODEL_MISSING`(409). (Task 5, 7)
5. **`nvidia-smi`가 없거나 멈추거나 이상한 값을 냄** → 5초 시간 초과 후 `integrated` 등급. (Task 2)
