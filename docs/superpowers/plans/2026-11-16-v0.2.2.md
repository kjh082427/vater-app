# v0.2.2 계획

설계: [v2 설계 22장](../specs/2026-11-05-v2-design.md). 작업마다 테스트를 먼저 쓰고, 작업 하나가 끝나면 커밋하고 push한다. 브랜치마다 PR(템플릿 4항목, `area:*` 라벨)을 열고 CI를 통과하면 merge 커밋으로 합친다.

지킬 것: 보유 내역은 AI로 보내지 않는다(`privacy.test.ts`, `test_no_personal_data_to_ai.py`). 주문 API는 만들지 않는다. `uv run`은 `env -u VIRTUAL_ENV`로 부른다.

## 1. `core/v022`: 보유 내역은 [올리기]로만
- 시험 먼저(`sidecar/tests`)
  - 연결해도 보유 내역이 저장되지 않는다(연결 시험 `adapter.test()`는 그대로 부른다).
  - 앱 시작, 주기, 자산 추이 기록에서 증권사를 부르지 않는다.
  - `POST /holdings/sync`(올리기)는 지금처럼 받아 저장한다.
  - 자산 추이와 평가는 저장된 수량과 시세로 계산한다.
- 고칠 곳
  - `holdings/service.py`: `_connect`의 `replace_api`를 지운다. `_run`의 시작 동기화, `tick_once`와 주기 반복을 지운다.
  - `portfolio/daily.py`의 `_sync_once`를 지운다.
  - `store/settings.py`의 `holdings.sync_minutes`를 지운다. DB에 남은 옛 값을 읽어도 오류가 나지 않는지 확인한다(마이그레이션 시험 `migrate.accept.ts`).
  - 시험 `test_holdings_api.py`, `e2e/acceptance/v2.accept.ts`(V4 주기 설정)를 새 동작에 맞춘다.
- OpenAPI 스냅샷을 갱신하고 `docs/brokers/*.md`와 앱 README의 "연결하면 받아 온다" 문구를 고친다.

## 2. `ui/v022`: 화면
작업 하나마다 커밋한다.
1. **홈 흔들림:** `mock.html`을 Playwright(로컬 chromium 있음)로 열고 창 너비를 1px씩 바꿔 영역 크기가 멈추지 않는 지점을 찾는다. 그 상황의 시험을 만든 뒤 `dashboard.module.css`의 `.area`에 `scrollbar-gutter: stable`를 넣는다. 안 되면 `SplitLayout.tsx`의 `useAreaSize`가 스크롤되지 않는 바깥 상자를 재게 한다.
2. **보유 종목 고르기 묶음:** `HeldSymbolChoices.tsx`에서 한국·미국 두 묶음으로 나눈다. `privacy.test.ts`의 `onPick` 검사는 그대로 통과해야 한다.
3. **감시 종목 한꺼번에 빼기:** `AlertsScreen.tsx`와 `WatchPanel.tsx`에 체크 상자, "N종목 선택", 확인 창을 둔다. `AnalysisHistory`, `DeleteAnalysisDialog`의 방식을 따른다. 사이드카에 일괄 삭제 API가 없으면 `DELETE /watchlist/{id}`를 차례로 부르고 실패한 종목은 이유를 보인다.
4. **올리기 창 기본 체크 해제:** `UploadDialog.tsx`의 `setChecked`(약 148행)에서 미리 체크하지 않는다. 위에 [모두 선택]·[모두 해제] 버튼을 둔다.
5. **보유 종목에서 불러오기:** `AlertsScreen.tsx`에서 [보유 종목 직접 추가]와 `ManualDialog`를 빼고, [보유 종목에서 불러오기]와 새 창을 넣는다. 창은 저장된 `/holdings` 가운데 감시 중이 아닌 종목만 보이고, 처음에는 모두 해제, [모두 선택]·[모두 해제]를 둔다. 고른 종목은 `POST /holdings/watch`(규칙 없이)로 넣는다. 4번과 겹치는 목록·체크 부분은 함께 쓴다. v0.2.1에서 되살린 시험(`AlertsScreen.test.tsx`의 직접 추가 시험)은 새 동작으로 바꾼다.
6. **새로고침:** `HoldingsScreen`과 `AlertsScreen`의 `ScreenHeader end`에 [새로고침]을 두고, 그 화면의 `useResource`를 모두 `reload`한다. `/holdings/sync`는 부르지 않는다.
7. **설정 화면:** `SettingsScreen.tsx`에서 보유 내역 주기 조회 항목을 뺀다(1번 브랜치와 짝).
- 마무리: `npx vitest run`, `tsc`, `eslint`, `prettier --check`, `npm run e2e:holdings`. `apps/desktop/README.md`를 고친다.

## 3. `infra/security`: CI
- `ci.yml`의 sidecar 작업에 `uvx pip-audit`(uv.lock에서 내보낸 목록 대상)를 넣는다.
- `ci.yml`의 desktop-ui 작업에 `npm audit --omit=dev --audit-level=high`를 넣는다.
- `desktop.yml`에 `cargo audit`를 넣는다(`rustsec/audit-check` 대신 `cargo install cargo-audit --locked`).
- 처음 돌렸을 때 이미 있는 취약점은 고칠 수 있으면 올리고, 못 고치면 이유와 함께 무시 목록에 적는다.
- `release.yml`, `release-acceptance.yml`의 `uses:`를 커밋 해시로 바꾸고 뒤에 버전 주석을 단다(`actions/*`, `astral-sh/setup-uv`, `Swatinem/rust-cache`).
- `docs/TOOLING.md`에 pip-audit, npm audit, cargo-audit를 적는다.

## 4. 보안 리뷰
- 시작 전에 사용자에게 묻는다(토큰 10~15만 예상). 모델은 기본 또는 Opus, 노력 high. Fable은 쓰지 않는다.
- 범위: `sidecar/src/vater_core/{api,secrets,brokers,holdings}`, `logging_setup.py`, `apps/desktop/src-tauri`(권한·CSP·updater), `apps/desktop/src/api`. 볼 것은 22장 10번에 적은 항목이다.
- 나온 문제는 영역 브랜치(`core/security-*`, `shell/security-*`)에서 시험을 먼저 쓰고 고친다.
