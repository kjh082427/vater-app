# core/kis 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한국투자증권 Open API 연동 계층을 만든다. 범위는 다음과 같고, 모두 **읽기 전용**이다(주문 없음).
- 토큰·승인키 캐시
- 우선순위 호출 제한
- 국내·해외 시세, 일봉, 휴장일
- 국내 재무·뉴스 (검증 실험 S2에서 정한 국내 분석 공급자용)
- 시장 데이터 (브리핑용)
- 실시간 WebSocket
- 종목 마스터와 검색 API
- 연결 테스트 API

**Architecture:**
- **`KisClient`**: 주입받은 `httpx.AsyncClient`로 인증 헤더, 우선순위 호출 제한, `EGW00201` 재시도, 오류 변환을 맡는다.
- **`quotes`, `fundamentals`, `market`**: TR마다 하나씩 있는 얇은 타입 함수다.
- **`TokenManager`**: 토큰을 `SecretName.KIS_ACCESS_TOKEN`에 JSON으로 캐시해서 앱을 다시 켜도 재발급하지 않는다. **발급할 때마다 사용자에게 알림톡이 가기 때문이다.**
- **`KisRealtime`**: websockets로 접속해 구독, `PINGPONG` 응답, 재연결과 재구독을 처리하고 `Tick`을 콜백으로 넘긴다.
- **테스트**: REST는 respx로, WebSocket은 로컬 가짜 서버(`websockets.serve`)로 한다.

**Tech Stack:** httpx, websockets, respx(dev), 기존 core/foundation(`AppDeps`, `VaterError`, `SettingsRepo`/`SETTING_DEFS`, `SecretStore`/`SecretName`, `EventBus`)

**Spec:** `docs/superpowers/specs/2026-11-02-vater-mvp-design.md` (7장, 4-2, 6장, 13장 S2 결론). 공식 샘플 조사 결과는 아래 부록 A에 있다.

## Global Constraints
- 브랜치 `core/kis`. 폴더는 `sidecar/src/vater_core/kis/`이고, 추가로 `api/routes/kis.py`, `store/migrations/002_symbols.sql`, `store/settings.py`(키 추가)를 건드린다. PR 라벨 `area:core`
- **호스트**
  - REST: 실전 `https://openapi.koreainvestment.com:9443`, 모의 `https://openapivts.koreainvestment.com:29443`
  - WS: 실전 `ws://ops.koreainvestment.com:21000`, 모의 `ws://ops.koreainvestment.com:31000`
- **REST 공통 헤더**: `content-type: application/json; charset=utf-8`, `authorization: Bearer <token>`, `appkey`, `appsecret`, `tr_id`, `custtype: P` (연속 조회는 `tr_cont`)
- **토큰**
  - 응답 `access_token_token_expired`(KST `YYYY-MM-DD HH:MM:SS`)를 저장하고 **만료 1시간 전**에 재발급한다.
  - `asyncio.Lock`으로 한 번에 1번만 발급한다.
  - 캐시 JSON은 1000자 이하로 유지한다(Windows 자격 증명 관리자 크기 제한 대비).
- **호출 제한 설정 키**
  - `kis.rate_per_sec.prod` = 15 (범위 1~20)
  - `kis.rate_per_sec.vps` = 2 (범위 1~5)
  - `kis.ws_max_subscriptions` = 41 (범위 1~41)
- **재시도**: `EGW00201` → 0.5초, 1초, 2초 대기 후 최대 3회. 재시도 간격은 생성자 인자로 바꿀 수 있게 한다(테스트에서 0초).
- **우선순위**: `Priority.ALERTS = 0` > `BRIEFING = 1` > `MASTER = 2`
- **WS 재연결 간격**: `(1, 2, 4, 8, 16, 32, 60)`초. 마지막 값을 계속 쓴다.
- **오류 코드** (`VaterError`)

  | 코드 | 상황 | HTTP |
  |---|---|---|
  | `KIS_NOT_CONFIGURED` | 키 없음 | 409 |
  | `KIS_AUTH_INVALID` | 키 거부 | 401 |
  | `KIS_RATE_LIMITED` | 재시도 소진 또는 토큰 발급 1분 제한 | 429 |
  | `KIS_API_ERROR` | `rt_cd ≠ "0"`, `message`에 `msg1` | 502 |
  | `KIS_UNREACHABLE` | 네트워크 오류 | 503 |

- **주문·정정·취소 TR과 경로는 금지**한다 (`tests/test_readonly_guarantee.py`가 강제).
- 실연동 테스트는 `@pytest.mark.kis_live`로 표시하고 기본 실행에서 제외한다. 실연동 전체에서 **토큰 발급은 1번만** 한다(캐시 재사용).
- **SQLite 쓰기는 이벤트 루프 스레드에서만** 한다 (core/foundation 리뷰에서 넘어온 규칙).

## Review Focus
1. **앱을 다시 켤 때마다 토큰 재발급 → 알림톡 폭탄** → 캐시된 토큰이 유효하면 `/oauth2/tokenP`를 부르지 않는다 (Task 2)
2. **여러 요청이 동시에 첫 토큰을 요청** → 발급 호출은 정확히 1번 (Task 2)
3. **HTTP 200인데 `rt_cd`가 "1"** → `KIS_API_ERROR`로 변환하고 `msg1`을 message에 넣는다. HTTP 500에 `EGW00201` 본문이 와도 재시도한다 (Task 3)
4. **장 마감 후나 휴일에 현재가 조회** → 마지막 체결가가 그대로 오며 오류가 아니다. 장이 열렸는지는 휴장일 API로 판단한다 (Task 4)
5. **WebSocket이 끊긴 뒤 재연결** → 이전 구독이 모두 복원된다. 한도를 넘는 구독은 `False`를 돌려줘서 호출자가 폴링으로 대체하게 한다 (Task 7)

### Task 7: 실시간 WebSocket (`ws.py`)
**Interfaces — Produces:**
- `@dataclass(frozen=True) Tick(market: Market, code: str, price: float, change_pct: float, volume: int, at: str)`
- `class KisRealtime:`
  - `__init__(self, tokens, server, on_tick: Callable[[Tick], None], on_state: Callable[[str], None] = noop, max_subscriptions: int = 41, url: str | None = None, backoff: tuple[float, ...] = (1, 2, 4, 8, 16, 32, 60))`
  - `async def subscribe(self, market, code, exchange: UsExchange | None = None) -> bool`: 한도를 넘으면 `False`
  - `async def unsubscribe(self, market, code, exchange=None) -> None`
  - `async def run(self) -> None`: 취소될 때까지 돈다
  - `state: Literal["connecting", "connected", "reconnecting", "stopped"]`
- 구독 메시지: `{"header": {"approval_key", "custtype": "P", "tr_type": "1"|"2", "content-type": "utf-8"}, "body": {"input": {"tr_id", "tr_key"}}}`
  - 국내: `tr_id = "H0STCNT0"`, `tr_key = 종목코드`
  - 미국: `tr_id = "HDFSCNT0"`, `tr_key = "D" + 거래소 + 종목` (예: `"DNASAAPL"`)
- 수신 처리
  - 첫 글자가 `{`이면 시스템 메시지다. `header.tr_id == "PINGPONG"`이면 **받은 문자열을 그대로** 돌려보낸다.
  - 그 외에는 `"0|TR_ID|건수|f^f^..."` 형식이다. 건수만큼 레코드를 나눈다.
